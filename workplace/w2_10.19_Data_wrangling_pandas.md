# 옷장패션 데이터 정제 보고서

## 1. 데이터 개요

- 행/열: 1,500 × 8
- 주요 컬럼: order_id, customer_age, category, channel, price, quantity, amount, return_amount

## 2. 진단 결과

- 결측: amount 3.40%, price 0.33%
- 이상치(IQR): customer_age(999·0, 18건), quantity(200, 1건), amount(50,000,000, 145건)
- 의심되는 결측 유형: amount는 app 채널에 쏠림 → MAR

## 3. 처리 결정과 근거

| 이슈                                 | 결정                                       | 근거                                                                                 | 한계                                                                                                                                     |
| ------------------------------------ | ------------------------------------------ | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| customer_age 불가능 값(999·0, 51건) | NaN 처리 후 전체 중앙값 대체               | 0세·999세는 물리적으로 불가능한 입력 오류이고, 5건뿐이라 대체해도 분포 영향이 작음  | 실제 나이는 알 수 없음. IQR로 잡힌 나머지 건은 드물지만 가능한 나이라 그대로 둠                                                          |
| quantity 이상치(200, 1건)            | NaN 처리 후 중앙값 대체                    | 다른 주문은 1~3개인데 개인 고객의 200개는 입력 오류일 가능성이 큼                    | 실제 수량을 알 수 없고, 대체 후 price × quantity가 amount와 맞지 않을 수 있음                                                           |
| amount 극단값(50,000,000, 1건)       | 삭제하지 않고 유지 + amount_outlier 플래그 | 도매 주문처럼 실제 거래일 수 있어 삭제하면 정보 손실                                 | IQR 플래그 145건 대부분은 정상적인 고액 주문이라 플래그만으로 도매 의심 건을 구분하기 어려움. 평균·합계 계산 시 이 1건을 따로 다뤄야 함 |
| amount 결측(51건)                    | 채널별 중앙값 대체                         | 결측이 app 채널에 쏠려 있어 MAR로 판단, 채널 안에서 채우는 게 전체 중앙값보다 합리적 | 같은 채널이라도 주문 내용은 제각각임. price × quantity로 직접 계산할 수 있는 행은 계산값이 더 정확함                                    |
| price 결측(5건)                      | 카테고리별 중앙값 대체                     | 상품 가격은 카테고리와 관련 있다고 가정                                              | 이 데이터는 가격이 카테고리와 무관하게 배정되어 효과가 제한적. amount ÷ quantity로 역산하는 방법이 더 정확할 수 있음                    |
| return_amount의 0                    | 결측으로 보지 않고 유지                    | 0은 "반품 없음"이라는 의미 있는 값                                                   | 반품 기록이 아예 누락된 경우와 구분할 수 없음                                                                                            |

## 4. 처리 후 검증

- 결측 0건(설계상 NaN 유지가 필요한 컬럼 제외)
- customer_age 범위: 5 ~ 60 (정상)
- amount_outlier 플래그 145건 보존
